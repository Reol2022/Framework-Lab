# 开源与私有边界

## 可开源内容

- 通用工作流、Schema、CLI 和脚本。
- 提示模板及其公开约束。
- 基于公开框架、带版本和证据的知识卡。
- 测试任务、最小复现和公开问题报告。
- 脱敏后的聚合指标。
- 独立实现的框架适配器和通用迁移方法。

公开前必须检查来源许可、个人信息、凭证、内部标识和可逆脱敏风险。

## 必须保持私有的内容

- GaitLogic 生产数据、用户账号和训练记录。
- 服务器配置、密钥、令牌、凭证及生产地址。
- 未公开的商业化方案。
- 导师、同门或实验室未公开资料。
- 同门文档原文、截图、私有提示词和内部会议记录。
- 可识别真实用户的信息或可与其他数据重新关联的信息。

## 独立设计要求

项目可以受实验室讨论启发，但公开成果必须来自独立设计、独立 Schema、独立实现和独立实验结果。不得通过改写、翻译或重新排版规避对未公开材料的复制限制。若无法证明内容来源可公开，则保持私有并在公开仓库中只记录抽象需求。

## 提交检查

贡献者应检查 Git 差异、示例数据、日志、截图和测试产物；发现疑似秘密或私有材料时停止提交，先撤除并确认是否需要轮换凭证。公开问题报告只保留最小、脱敏、可复现的内容。
