# v0.1.3 日志解析与结构化错误事件实施报告

日期：2026-07-23

## 实施范围

本版本在 v0.1.2 基线证据之上增加确定性的日志解析、统一 ErrorEvent、SHA256 fingerprint、去重、阻塞错误选择、`errors.json`、新运行报告摘要和历史 Run 回放。解析输入只包括运行元数据和已保存日志，不读取框架源码进行推断。

未实现根因推断、修复建议、LLM 分析、自动修复、知识卡、浏览器自动化或多框架并行。

## 解析器与优先级

registry 按以下优先级运行：

1. ESLint
2. Sass
3. Vite
4. TypeScript
5. Node
6. pnpm/npm lifecycle
7. generic fallback

generic 只在失败或超时步骤没有专属结果时生成一条低置信度事件。Sass/Vite/Node 的重叠条件受到限制，避免把同一具体错误复制为多份等价事件。生命周期事件可以保留，但不能覆盖更具体的阻塞事件。

## 规范化与隐私

- 清理 ANSI，统一 CRLF/LF 和分隔符。
- source root 与 Framework Lab 根目录中的路径相对化。
- 根目录外机器路径在事件与 fingerprint 输入中脱敏。
- `rawExcerpt` 最长 1200 字符。
- fingerprint 包含 parser、tool、category、文件、位置、规范化消息、rule/code 和 stepId。

结构化事件只记录日志明确提供的事实，不包含 `rootCause`、`recommendedFix` 或 `businessImpact`。

## 测试

项目测试共 38 项，覆盖 v0.1.2 的 10 项回归和 v0.1.3 的 28 项解析测试。解析测试覆盖 Sass、ESLint、Vite/Rollup、TypeScript 两种位置格式、Node、pnpm、generic、ANSI/CRLF、路径相对化/脱敏、fingerprint、去重、阻塞选择、空日志、Schema、历史覆盖控制、缺失日志、旧 Schema 和报告上限。

## Schema 兼容

`error-events.schema.json` 验证新 `errors.json`。baseline Run Schema 的三个新字段均为 optional，旧 Run 结构仍通过校验。事件 id 唯一性在运行时代码中检查。

## 当前限制

- 正则解析只覆盖已测试的常见文本格式，不代表工具语义理解。
- `recognized` 表示命中确定性 parser，不表示结论正确率或根因置信度。
- 历史回放不回写旧报告；新 baseline 才自动在 `run.json/report.md` 中引用错误摘要。
- 尚未在 NCom 之外的真实框架日志上验证。

## 开源与私有边界

parser registry、解析器、类型、Schema、脱敏 fixture、fingerprint/去重逻辑、报告生成和脱敏示例适合开源。原始日志、本地源码 worktree、依赖、构建产物和未脱敏真实错误材料保持本地或忽略。
