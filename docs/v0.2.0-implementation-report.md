# Framework Lab v0.2.0 实施报告

## 完成范围

v0.2.0 实现了任务定义、检索与 Context 绑定、detached worktree、结构化 Acceptance、Change Policy、Verification Plan、Handoff、Diff 检查、独立验证、ErrorEvent、Before/After 对照、Manifest 和 append-only History。核心不调用 Coding Agent 或 OpenAI API，不生成代码，不自动接受、commit、merge 或 push。

v0.1.8 表明 Context 能减少部分探索，但未证明固定 Token 节省或必然提高代码质量；因此本版把验收条件、theme-build 前置链、人工浏览器状态和 Agent 自报的外部复核固化为结构化证据。

## 实现说明

- 所有路径以仓库根目录解析，公开产物不保存机器绝对路径。
- 命令继续复用既有 `spawn`、超时、stdout/stderr 和 ErrorEvent 基础设施。
- HTTP 步骤在配置 timeout 内轮询服务就绪，避免把进程刚启动时的连接失败误记为框架失败。
- 状态变化写入一行一个事件的 `task-history.jsonl`，Manifest 覆盖任务输出哈希。
- 不可观测的 Agent 搜索、文件读取、Token usage 保持 `null`。

## 真实验证摘要

真实任务绑定 NCom commit `a350b576bbeae6c6254273037a17d2a8730fb80f`。Policy 通过；install、theme build、example build、开发服务器与 HTTP 200 通过；18 项自动验收通过；浏览器点击为 `manual_required`；任务状态为 `verification_partial`。详见 [真实任务报告](v0.2.0-ncom-task-report.md)。

## 限制

当前只在 NCom 上完成真实闭环。Agent 修改仍由用户启动外部会话；Agent 自报指标可能不完整；Token usage 不可用；浏览器行为需要人工确认；配置验收通过不等于所有功能正确。
