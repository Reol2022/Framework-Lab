# NCom v0.2.3 Knowledge Quality

## 评估方式

质量报告逐维记录，不合成伪精确总分：

- Evidence validity
- Freshness
- Type completeness
- Symbol reachability
- Public API support
- Workflow verification
- Ambiguity
- Conflict status

## 当前结果

| 指标 | 结果 |
|---|---:|
| Published units | 22 |
| Evidence validity = high | 22 |
| Freshness = current | 22 |
| Type completeness = low | 0 |
| Overall quality = high | 18 |
| Overall quality = medium | 4 |
| 严格结构化冲突 | 0 |
| 自动解决冲突 | 0 |

`high evidence` 只表示每个 Claim 绑定了合法 Bundle Evidence id 且通过 SHA/Scope 校验，不表示 Claim 已经过运行或浏览器验证。4 个带 Recipe 但缺少运行验证的单元被限制为 `overallQuality: medium`，不能评为 high。

## 冲突检测边界

Conflict Detector 检测标准化后完全相同的跨单元 Claim，以及相同 structured target/claim key 的不同 `value:*` 标签。它不使用文本相似度猜测矛盾，也不自动删除或覆盖知识。当前 0 个结果只能解释为“未发现这两类严格结构化冲突”。

## 已知不足

- `documentCoverage` 与 `exampleCoverage` 仍依赖 Knowledge evidence 的类型标注，不能用 related path 数量替代。
- 组件家族是结构归纳，不能提升成员 Claim 的行为置信度。
- 人工复核记录由本次 Codex 辅助实施会话显式执行，仍应由项目维护者抽检。
- 质量维度未经过跨框架校准。
