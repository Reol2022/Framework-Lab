# Framework Lab v0.2.3 实施报告

## 目标与边界

本版本在 v0.2.2 之上扩展 NCom 知识覆盖、结构化组件族、多任务 Context 对照和外部 Agent Demo。核心仍是确定性的本地 CLI；Framework Lab 不自动调用 Codex/OpenAI API，不提供 Agent Runtime、自动修复、浏览器自动化、向量数据库或第二框架支持。

## 实现

- 新增 Gap Analyzer 与透明 Priority Model。
- 新增只使用 `base:*`、`event:*`、`slot:*` 信号的 Component Family Analyzer，以及显式 `review-family`。
- 新增 Knowledge Quality、严格结构化 Conflict Detector 和 Economics 汇总。
- 新增 12 项 Evaluation Set、Raw/Knowledge-first Context 生成与 Schema 校验。
- Knowledge-first 检索顺序为：精确组件、已复核家族、机制、工作流、验证知识、Raw fallback。
- 发布知识从 6 个增加到 22 个；新增 4 个机制、3 个家族、6 个组件和 3 个工作流单元。

## 关键事实

- NCom scope：`a350b576bbeae6c6254273037a17d2a8730fb80f`。
- 当前 Catalog 与 Symbol Snapshot 未重新扫描或覆盖。
- v0.2.2 真实 diff 仍为 6 个旧知识单元、0 个 affected；本版本没有据此伪造 relearning。
- 组件族只表示共享结构信号。3 个家族均通过显式 CLI 复核，并保留限制。
- 22 个 published unit 的 Claim 都有 Bundle Evidence id；这不表示所有行为都经过运行或浏览器验证。

## 评测

固定 12 个任务的最终 Context 对照中，Raw 估计 tokens 平均 `1844.5`，Knowledge-first 平均 `1402.17`；12 个任务的 Knowledge-first Context 均更短，启发式 must-recall 为 `1.0`。全部 12 项人工质量复核仍为 `pending`，因此不能据此宣称开发质量提升或真实 token 节省。

首轮过宽召回被保存在 `results-first-pass.json`：Knowledge-first 平均 `2119.42`，7 个任务更长。该失败促使停止词、精确标识符过滤和单次最多 6 个知识单元的规则收紧。

## 外部 Agent

外部 Codex 会话由实施者手动启动，不是 Framework Lab 自动调用：

- Learning Agent：真实 Draft 首次通过 preflight、import 和 validate；因没有可发布 Claim，保留为 Draft。
- Demo A：Knowledge-first NCCard 示例，targeted lint 与 root build 通过。
- Demo B：Raw 与 Knowledge-first 各一个独立 worktree；两组均完成并通过 lint/build。
- Demo B Knowledge-first 记录 0 次搜索，Raw 记录 2 次；但 Knowledge-first 的读取命令和真实 input tokens 更高。单样本不支持总体收益结论。

## 风险与未验证项

- 组件族不是完整语义理解。
- Evaluation must-recall 是字符串启发式；unsupported claim 仍需人工判断。
- Agent Demo 未运行真实浏览器交互。
- Codex 成功会话 JSONL 未暴露默认模型名，因此模型字段保持 `null`。
- 当前只验证 NCom；不能外推至其他框架、Windows 版本或生产任务。

本版本新增和修改知识单元，已通过现有 Bundle、Draft、validate、review、publish 流程；不需要创建与本实现报告重复的旧式 KnowledgeCard。
