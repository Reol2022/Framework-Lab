# 任务规范

## 任务等级

- `L0`：环境、安装、构建、静态检查和最小启动。
- `L1`：验证单一概念的最小任务。
- `L2`：组合组件或多个概念的任务。
- `L3`：页面级行为和交互任务。
- `L4`：跨模块、工程化或发布相关任务。
- `L5`：真实项目中的渐进式迁移任务。

高等级不只表示代码更多，也表示依赖知识、回退成本和验证范围更大。任务升级前需证明前置等级稳定。

## 必备内容

每个任务必须包含：

- 任务目标与明确非目标。
- 前置知识及其版本。
- 输入上下文和允许额外读取的规则。
- 允许与禁止修改的路径。
- 可观察、可执行的验收标准。
- 执行命令及预期结果。
- 完成后的实际结果和证据。
- 失败归因。
- 知识新增、修订或复核建议。

结构以 [task Schema](../schemas/task.schema.json) 为准。

## 执行规则

执行前确认框架 commit 与知识卡一致；不一致时暂停并标记相关知识 `needs-review`。执行中记录超出上下文包读取的文件。完成后逐项填写实际结果，未运行的命令不得标记通过。

## 验收与失败

验收标准应描述可观察行为和允许偏差，不能仅写“工作正常”。失败使用工作流定义的类别，并保存最小复现或阻塞条件。因环境缺失无法执行与执行后失败必须分开记录。
