# v0.1.7 任务级检索与最小 Agent Context 实施报告

日期：2026-07-23

## 实现

新增确定性 TaskProfile、候选召回、透明评分、关系深度扩展、Scope 筛选、诊断降权、Catalog 约束片段读取、启发式预算裁剪以及 `retrieval query/validate/explain`。既有 `context create` 继续作为唯一 Context 入口；有有效 Catalog/Symbol Snapshot 时融合框架知识，无可用 Snapshot 时回退到 v0.1.4 KnowledgeCard 流程。

检索器不调用 LLM、embedding、向量数据库或外部服务。业务 hash 不包含生成时间。源码片段读取前检查 HEAD、tracked clean 和 Catalog SHA256，只输出入选行范围。

## 评分和关系边界

精确 Symbol/Component、公开可达性和完整导出链优先。组件扩展到 Props、成员、事件、样式、文档、示例与 package；Symbol 只沿有解析证据的 extends/implements/type reference 正向扩展。known issue 与 verified patch 必须命中特定任务词并通过 commit Scope，不因通用框架名进入组件使用任务。

受限 TypeScript resolver 的 unresolved 关系降低 confidence；语法结果仍可用。普通自然语言不用于猜测运行时调用图或设计意图。

## 预算

估算为 `ceil(characterCount / 4)`，不是精确 tokenizer。裁剪以完整候选、完整 snippet、完整 claim 为原子，不截断 signature、claim 或代码块。精确主组件/主 Symbol 保持在排序前部；预算不足以容纳最小内容时返回错误。

## 安全与兼容

- Retrieval 与 Context 本地产物默认忽略。
- 未复制完整 NCom 文件到公开报告。
- Context/Manifest Schema 只增加 optional 字段，旧 v0.1.4 格式继续通过。
- 未修改 Run 001–010、Catalog Snapshot、Symbol Snapshot、NCom 补丁、NCom/GaitLogic 源码。
- 本版本生成 Context，但不调用 Coding Agent。

## 验证

检索专项使用小型 Git/Catalog/Symbol/Knowledge fixture，覆盖 TaskProfile、召回、Scope、图深度、去重、透明评分、片段 commit/hash/行号、tracked dirty、SHA 不匹配、预算、Schema、旧 Context 和确定性。最终全量测试结果以本轮结束校验为准。

最终结果：

- `pnpm lint`：通过。
- `pnpm test`：287/287 通过，其中 v0.1.7 Retrieval 专项 78/78。
- `pnpm typecheck`：通过。
- `pnpm build`：通过。
- `git diff --check`：通过。
- Catalog、Symbol、Knowledge 与三个真实 Retrieval 校验均通过。

## 限制

确定性名称和关系检索不是自然语言语义理解或 RAG。中文任务依赖显式标识符、文档和配置 alias；TypeScript resolver 不完整会影响关系置信度。compression ratio 只比较入选片段字符与对应完整候选文件字符，不能解释为真实 Agent Token 节省。
