# 测试策略

## 验证层次

- **环境验证**：操作系统、运行时、包管理器、浏览器和必要工具。
- **静态验证**：格式、类型、lint、Schema 和配置检查。
- **构建验证**：安装、编译、打包和产物检查。
- **运行验证**：服务启动、入口加载和运行时错误。
- **行为验证**：用户可观察的交互、状态变化和输出。
- **边界验证**：空值、错误输入、极限条件和恢复行为。
- **兼容性验证**：声明支持的运行时、浏览器和依赖组合。
- **性能验证**：明确数据规模、环境、指标和基线后的测量。
- **人工体验验证**：可用性、反馈、可理解性和视觉异常。

## v0.1 优先顺序

1. 跑通安装与构建。
2. 执行仓库实际提供的静态检查。
3. 建立最小行为测试。
4. 建立浏览器冒烟测试。
5. 输出可复现报告。

在读取目标仓库并锁定 commit 前，不假定 NCom 使用任何具体测试框架、包管理器或命令。

## 记录要求

每次验证记录 commit、环境、命令、开始与结束时间、退出状态、关键输出和产物位置。预期结果与实际结果分开；跳过、未运行和失败不能合并为“未通过”。日志公开前必须脱敏。

## 通过条件

只有实际运行且满足验收标准的检查可以标记通过。人工观察应注明观察者与范围；性能结论必须有重复次数和对照基线；兼容性不能从单一环境推断。
