# v0.1.2 可执行基线运行器实施报告

日期：2026-07-23

## 实施范围

本版本实现最小可运行的 `framework-lab baseline run` CLI。实现范围包括框架配置加载、Schema 校验、环境与 Git 状态采集、串行命令运行、超时终止、运行编号预留、结构化证据及 Markdown 报告。未实现自动修复、日志智能分析、知识自动生成、浏览器自动化、Web UI 或多框架并行。

## 配置与产物

NCom 配置位于 `frameworks/ncom/framework.yaml`，使用仓库相对路径指定源码和固定 pnpm 10.26.1。实际运行产物写入本地 `frameworks/ncom/runs/<run-id>/`：

- `run.json`
- `environment.json`
- `source.json`
- `steps/*.stdout.log`
- `steps/*.stderr.log`
- `report.md`

运行目录被 Git 忽略，因为原始日志及环境信息可能包含机器路径；公开报告应先脱敏。

## 实现验证

使用仓库固定 pnpm 10.26.1 执行：

```text
pnpm lint
pnpm test
pnpm typecheck
pnpm build
pnpm framework-lab --help
pnpm framework-lab baseline run does-not-exist
pnpm framework-lab baseline run ncom --dry-run
```

结果：lint、10 项测试、typecheck 和 build 全部通过。未知框架返回退出码 1。dry-run 预览 `run-008`，运行目录数量在前后均为 0，因此未执行 NCom 命令或创建运行产物。

测试覆盖配置加载、run id 递增、成功命令、非零退出、`allow_failure`、阻塞后跳过、超时、Windows `.cmd` 参数、dirty Git worktree 和 Markdown 报告。

## 真实 NCom 基线

Run 008 首次验证了完整流程，同时暴露 npm 命令被 pnpm 注入 PATH 中错误 shim 遮蔽的问题。该次证据被保留，未覆盖或删除。运行器随后改为在 Windows 从当前 `node.exe` 同目录解析 `npm.cmd`，并重新通过全部项目检查。

修正后的权威结果为 Run 009：

- NCom commit：`a350b576bbeae6c6254273037a17d2a8730fb80f`
- Node：`v24.18.0`
- npm：`11.7.0`
- pnpm：配置与实际均为 `10.26.1`
- install：`passed`，退出码 0
- lint：`failed`，退出码 1，日志报告 36 errors、10 warnings
- build：`failed`，退出码 1
- 最终状态：`failed`
- 首个阻塞步骤：`build`
- 总耗时：49.782 秒

build 日志记录的实际错误为 Sass 无法导入注入的、包含 CJK 绝对路径的 `packages/theme/index.scss`。本次未修改 NCom 源码或配置，也未执行自动修复。

Run 009 的 `run.json` 已再次显式通过 `baseline-run.schema.json`。运行前采集到 NCom worktree 为 dirty，变更列表只含未跟踪的 `node_modules/` 和 `dist/` 目录。运行后 `git diff --name-only` 为空；NCom 的 `package.json`、`pnpm-lock.yaml` 与 `packages/all/build/shared.ts` 均无已跟踪变更。当前仓库状态中不存在需要记录为本地修改的 `shared.ts`，因此报告没有虚构该项。

## 风险与边界

- 当前只有 NCom 配置经过真实运行，不能据此声称通用多框架支持已经验证。
- `.cmd` 适配依赖 Windows `cmd.exe` 的参数规则，已有含空格和中文路径的自动测试，但仍应在其他 Windows/Node 组合上复验。
- NCom lint 和 build 仍失败；本版本仅记录事实，不修改或归因框架源码。
- 自动运行目录包含原始证据且保持本地，不直接作为开源材料。
- 未新增或修改知识卡；本次任务不需要知识卡。
