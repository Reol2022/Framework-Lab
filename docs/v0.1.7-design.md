# v0.1.7 官方文档采集与多来源校验设计

## 实施位置

本能力按 v0.1.7 的原始目标补齐，但仓库当前版本已经是 v0.2.3，因此不回退版本号，也不覆盖 v0.1.7 原有的检索能力。实现复用现有 `framework.yaml`、Catalog、Symbol Snapshot、Ajv Schema 和 Context 目录。

## 数据流

1. `docs collect` 按配置选择 HTTP、browser、file 或 auto provider。
2. auto 先采集 HTTP，再解析正文并执行质量门禁；不足时仅回退 browser。
3. 原始正文写入不可覆盖的本地 snapshot，元数据只保存相对路径和 SHA256。
4. `docs parse` 校验结构化 DocPage/DocComponent。
5. `knowledge reconcile` 合并 official-doc、type-definition、source-code 和 official-example；test/runtime-record 由同一模型支持，但本轮 NCom 没有新运行时证据。
6. 冲突与覆盖分别生成 JSON 和 Markdown。
7. `context build` 只选择指定组件的公共 API、有界示例、证据状态、冲突和命令。

## 关键约束

- HTTP 200 不是成功判据。
- 无法解析的值保持 `null`，不补造默认值、类型或描述。
- `verified` 需要两个独立来源一致或 runtime-record；单文档为 `documented`，单源码/类型为 `inferred`。
- 冲突报告只指出证据差异和人工核对动作，不推断根因或自动给出修复。
- rootHash 不包含时间和机器绝对路径。

## 兼容性

`docs` 是 `framework.yaml` 的可选节点，也可使用独立 `frameworks/<id>/docs.yaml`。NCom 使用独立文件，避免改变既有 KnowledgeCard 绑定的框架配置哈希。旧配置、baseline、errors、KnowledgeCard 和 Context v1 可继续读取；Context v2 使用独立 Schema 和 `context build` 命令，不替换 `context create`。
