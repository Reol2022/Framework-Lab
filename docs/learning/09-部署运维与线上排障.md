# 部署运维与线上排障

## 真实情况：没有线上部署

当前项目没有 Dockerfile、docker-compose、Nginx、域名、HTTPS、服务器、进程守护、生产环境变量或数据库连接配置。它不能作为“已部署线上 AI 应用”写入简历。

## 已实现的本地运行与排障能力

| 项目 | 当前实现 |
| --- | --- |
| 工具链 | Node、npm、固定 pnpm 版本与可执行路径记录 |
| 子进程 | `spawn`、stdout/stderr 分离、PID、timeout、Windows 进程树终止 |
| 开发服务 | Task Verification Plan 可启动背景服务、在 timeout 内轮询 HTTP |
| 日志 | baseline/Task 步骤日志、ErrorEvent、Markdown report |
| 停止 | BackgroundProcess 提供 stop；Run 007 记录 PID 和 `Stop-Process` 方法 |
| 排障顺序 | commit/dirty → 环境/pnpm → command/log → structured error → HTTP → 浏览器人工检查 |

## 本地排障顺序

1. 用 `git status --short` 和 `git rev-parse HEAD` 固定输入。
2. 记录 `node --version`、`npm --version`、固定 pnpm 版本和 `where.exe`。
3. 查看步骤 stdout/stderr，不只看 pnpm lifecycle 尾部。
4. 检查 timeout、PID、端口和服务是否提前退出。
5. 分别请求首页、入口模块和静态资源。
6. 最后打开浏览器做渲染、交互、Console/Network 人工检查。

## 未来部署前的必做事项

- 定义用户、项目和框架源码的权限隔离。
- 将原始日志、worktree、密钥和大产物从公开材料分离。
- 设计并发 run 的锁/队列、产物存储和清理策略。
- 确定 API/认证、限流、审计、监控、告警、备份和回滚。
- 为服务化后的 CLI/Worker/浏览器执行器分别建立健康检查和失败恢复。

## 安全边界

不得把 `.env`、凭据、用户名、机器绝对路径、内部 worktree、原始 Agent 会话或未脱敏日志公开。开源内容限于通用 CLI、Schema、测试 fixture 和脱敏报告。
