## 面试前必须能诚实回答的限制

- Context 的 token 是启发式估算，不是实际模型 usage。
- A/B 没有统计显著性、精确 Token 或浏览器点击验证。
- Catalog/Symbol/Impact 是结构化精确分析，不是语义理解。
- NCom 是唯一真实框架案例；未证明多框架通用性。
- 不是已部署产品；无数据库、无生产运维和无用户数据。
- Codex 是外部协作执行者，不是项目内自动调用的 API。

## 后续文档维护规则

每次功能完成、Bug 修复或重构后：

1. 在 `changelog/YYYY-MM-DD.md` 写目标、修改、证据、验证和限制。
2. 若改变用户可讲述能力，更新 `12-简历事实与证据清单.md`。
3. 若出现真实失败，更新 `05-开发过程问题与故障复盘.md`。
4. 若改变调用链或约束，更新 `02`、`04`、`07`、`08` 或 `10`。
5. 没有证据的结论保持“未验证”，不因计划存在而升级。
