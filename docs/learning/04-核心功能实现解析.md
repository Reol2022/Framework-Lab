# 核心功能实现解析

## 配置驱动 Baseline Runner

- **业务目标**：不靠人工回忆命令，重复执行框架 install/lint/build 并保存完整证据。
- **用户流程**：维护 `frameworks/<id>/framework.yaml` → `pnpm framework-lab baseline run <id>` → 查看 `runs/<run-id>/`。
- **调用链**：`cli/index.ts` → `config.ts` → `baseline.ts` → `environment.ts`/`git.ts` → `process.ts` → `errors.ts`/`report.ts`。
- **输入/输出**：输入为 YAML step、可选 run id/source dir；输出为 run/environment/source/errors JSON、分离日志和报告。
- **异常**：未知框架、非法配置、子进程非零、超时、Git 信息不可读；信息不可读时记录 null/warning，不直接伪造。
- **测试方式**：临时目录和 Node 小脚本覆盖 passed/failed/partial/skipped/timed_out、Windows cmd 参数和 dirty Git。
- **取舍**：不通过 `shell:true` 规避 Windows 引号；不自动修改框架。
- **面试讲法**：重点说状态机和证据落盘，而不是“我写了一个跑命令的脚本”。

## 结构化错误回放

- **业务目标**：从保存日志中得到可检索、可比较的错误事件，避免生命周期包装错误掩盖具体失败。
- **调用链**：`errors parse` 或 baseline 后置 → `error-normalize.ts` → `error-parsers.ts` → `errors.json`。
- **输入/输出**：输入 run 元数据和 stdout/stderr；输出 parser/tool/category/file/line/rule/rawExcerpt/fingerprint/blocking。
- **异常/边界**：空日志仍生成合法文件；未知格式使用一条 generic fallback；不输出根因推断和修复建议。
- **真实验证**：Run 009 的 blocking Sass error 与 Run 010 无 blocking error。
- **面试追问**：为什么要 fingerprint？答：在相同规范化输入下用于稳定去重和 before/after 比较。

## Catalog 与 Symbol 源码阅读

- **业务目标**：给陌生框架建立确定性、版本绑定的文件/包/文档/示例/符号地图。
- **调用链**：`catalog scan` → tracked files/hash/classification/workspace → `symbols extract` → TS AST/export/component/relationship。
- **输入/输出**：输入 Git worktree 和 framework 配置；输出 Snapshot、rootHash、Manifest 和 Diff。
- **异常/边界**：tracked dirty 默认拒绝；二进制/超大文件只记录元数据；不执行框架脚本；不解释运行时行为。
- **测试方式**：临时 Git fixture 覆盖 CJK/空格、rename、workspace、编码、dirty、语法与导出链。

## Retrieval 与最小 Agent Context

- **业务目标**：让 Agent 在有限上下文中得到任务相关的公开 API、示例、文档、约束和运行知识。
- **调用链**：`retrieval query` → Candidate/评分/关系扩展 → `context create` → 有限 source snippets + Manifest。
- **输入/输出**：输入 task、scope、snapshot、预算；输出 retrieval result 和 context。
- **异常/边界**：预算不足返回错误；sha/dirty 不匹配拒绝读取；没有 Snapshot 时回退旧 KnowledgeCard Context。
- **设计取舍**：不截断 claim/signature/代码块；只使用字符数估算 token；不是 RAG。

## 受控 Coding Agent Task

- **业务目标**：允许外部 Agent 修改代码，同时可限制范围、独立验证并保留历史。
- **调用链**：`task create` → `prepare` → `handoff` → 外部 Agent → `inspect` → `verify` → `compare` → `close`。
- **关键输入**：Acceptance、Change Policy、Verification Plan、Context、source commit。
- **关键输出**：worktree、patch、Policy 结果、Verification 报告、Comparison、append-only history。
- **异常/边界**：Policy 失败可阻止默认验证；manual/browser 条件不自动通过；关闭 accepted 需要人工确认。
- **真实验证**：NCom NCButton task 18 自动项通过、browser click manual_required。

## Learning 与版本失效传播

- **业务目标**：将受 Evidence 约束的框架知识发布，并在版本变化时只定位潜在受影响项。
- **调用链**：`learn plan/bundle/handoff/import/validate/review/publish`；`version diff` → `knowledge impact/freshness` → `refresh-plan`。
- **边界**：外部 Agent Draft 必须预校验；不自动 publish；精确 hash 不等于语义理解；verified Claim 迁移到目标 commit 通常仍需运行证据。
- **真实验证**：NCom 两个版本的结构 Diff 存在，但当前六个知识单元未被手工标 stale，impact 为 0。
