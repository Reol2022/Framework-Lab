# Framework Lab

> 面向小众、新兴、资料较少或快速变化的软件框架，构建可追溯、可验证、可更新的 AI 辅助学习与开发工作流。

**当前版本：** `v0.1.0-dev`  
**项目状态：** 早期实验阶段

## 项目背景

当框架资料稀少、版本变化快或缺少成熟生态时，普通笔记容易过期，通用 RAG 知识库也难以保证结论与具体版本、证据及验证结果一致。Framework Lab 以任务和实验为中心，把框架学习、知识沉淀、AI 开发、自动验证、问题反馈和版本更新连接成闭环。

## 要解决的问题

- 将框架结论绑定到明确的版本或 commit，并保留证据来源。
- 区分事实、推断、未知项和冲突，避免把 AI 推断当作事实。
- 为开发任务构建最小上下文包，减少无关信息和额外源码读取。
- 统一记录验证结果、失败归因、回归测试和知识更新。
- 在框架升级后识别受影响知识与任务，并重新验证。

## 核心工作流

锁定框架版本 → 建立源码与文档清单 → 设计学习地图 → 构建带证据的知识卡 → 生成任务级最小上下文包 → 指导 AI 开发 → 执行静态与行为验证 → 分类反馈问题 → 更新知识与回归测试 → 分析版本升级影响 → 通过门禁后进行真实项目的渐进式迁移。

详见 [工作流设计](docs/01-workflow-design.md)。

## 与普通笔记和通用 RAG 的区别

普通笔记重在记录，通用 RAG 重在检索；本项目重在“版本绑定、证据分级、可执行验证、任务验收和失效管理”。知识条目只有在满足验证条件后才能标记为已验证，框架变化会触发复核，而不是默认沿用旧结论。

## 当前阶段

当前只建立工作流、数据结构和基线模板：

- 尚未完成 NCom 学习，也未总结其框架能力。
- 当前没有经过验证的 NCom 知识结论。
- 尚未锁定 NCom commit，未执行安装、构建、示例或测试。
- GaitLogic 暂未进入重构或迁移阶段。
- CLI 仅有候选边界，本阶段不实现 CLI 代码。

## 首个实验对象：NCom

[New Component（NCom）](https://gitee.com/weblabsw/ncom) 用于验证这套工作流是否能支持资料较少框架的学习与任务开发。选择它不代表本仓库已经确认其 API、组件机制或实现细节；所有后续结论必须绑定实际 commit，并由源码、公开文档、官方示例或可复现实验支持。

## 仓库目录

- `docs/`：工作流和规范。
- `decisions/`：架构决策记录。
- `schemas/`：数据结构及示例。
- `prompts/`：提示类别的输入、输出和约束。
- `frameworks/`：按框架隔离的清单、学习地图、知识、任务和报告。
- `adapters/`：未来的框架适配边界。
- `cli/`、`scripts/`：未来自动化候选，不含实现。
- `metrics/`：运行记录格式和空数据文件。

## 版本路线

### v0.1.0：工作流骨架

- 初始化仓库、目录与 Schema。
- 定义开源边界。
- 创建 NCom 基线模板。

### v0.1.1：NCom 学习地图与环境验证

- 锁定 commit，执行安装和构建。
- 运行官方示例，完善学习地图。
- 创建第一个 L0 任务。

### v0.1.2：第一批证据型知识卡

- 选择少量核心概念。
- 阅读源码和公开文档，建立最小实验。
- 验证知识卡格式。

### v0.1.3：任务与测试闭环

- 创建 L1、L2 任务。
- 接入静态验证和浏览器验证。
- 记录 AI 执行数据。

### v0.1.4：问题反馈与知识更新

跑通“发现问题 → 最小复现 → 问题记录 → 修复或确认 → 更新知识 → 新增回归测试”。

### v0.2.0：框架无关化和 CLI 雏形

- 从 NCom 提炼通用流程并适配第二个框架。
- 根据已出现的重复工作实现最小 CLI。

### v0.3.0：GaitLogic 迁移试验

- 选择低风险页面并建立行为基线。
- 渐进式迁移，比较新旧行为。

## 开源与私有边界

本仓库只接收通用工作流、公开可追溯知识、脱敏指标和独立实验结果。生产数据、账号、密钥、服务器配置、内部会议材料、未公开商业方案及同门未公开材料必须保留在私有环境。详见 [开源边界](docs/02-open-source-boundary.md)。

## 贡献

请先阅读 [贡献指南](CONTRIBUTING.md) 和 [协作规则](AGENTS.md)。知识贡献必须给出版本、证据和验证方法；问题报告应提供最小复现。项目不接受未经验证的批量 AI 内容。

## 当前明确不做

- 不克隆或读取 NCom 源码，不生成 NCom 能力总结。
- 不修改或读取 GaitLogic。
- 不实现完整 CLI，不安装项目依赖。
- 不伪造框架 commit、API、测试或命令结果。
- 不复制私有材料或含敏感数据的内容。
