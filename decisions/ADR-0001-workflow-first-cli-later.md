# ADR-0001：先跑通工作流，后开发 CLI

- 状态：Accepted
- 决策范围：v0.1.x

## 背景

当前尚未通过真实框架任务验证流程，也无法确认哪些重复操作值得自动化。过早固定命令和内部模型会放大错误假设并增加迁移成本。

## 决策

先使用 Markdown、YAML、JSON Schema 和少量人工操作跑通基线、学习、知识、任务、验证、反馈和更新闭环；只有出现稳定、重复且可测量的操作后才开发最小 CLI。

## 原因

这些格式便于评审、版本控制和快速调整，足以验证数据结构与责任边界。人工执行能暴露真实步骤、必要输入和失败模式，为 CLI 提供证据。

## 优点

- 降低早期抽象和兼容负担。
- 让 Schema 与流程在实现前接受真实任务检验。
- 清楚区分必须自动化与适合人工判断的步骤。

## 缺点

- 初期重复操作较多，执行一致性依赖检查清单。
- 运行数据采集可能不完整。
- 在 CLI 出现前难以提供一键体验。

## 重新评估条件

当至少一个框架完成基线和任务闭环、相同操作稳定重复、输入输出可由 Schema 表达、错误处理和回退条件明确，并能为候选命令编写验收测试时，重新评估 CLI 范围和命令名称。
